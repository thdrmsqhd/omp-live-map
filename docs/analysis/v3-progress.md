# OMP Live Map V3 진행 현황

V3는 기존 합의에 따라 Phase 4~6을 대상으로 합니다. V2의 Windows 설치 및 단일 Loop는 V2 브랜치에서 유지합니다. V3의 워크플로우 정의는 기존 프로젝트와 Loop 정의를 재사용하고, V2 관측 API의 세션 그래프와 별도 경로에서 편집합니다.

| Task | 구현 | 검증 |
| --- | --- | --- |
| T031 (REQ-018, REQ-021) | Start, End, Agent, Command, Loop, Condition, Parallel, Join, Approval, 입출력 포트와 산출물 참조, Agent/Loop 버전 고정, SQLite v1 → v2 마이그레이션 | 정의 재조회, 프로젝트 경계, 참조된 정의 보호, 이전 버전 보존 |
| T032 (REQ-019) | 도달성, 선행관계, 중복·누락 포트, 순환, 구조화 조건, 산출물 경로 검증 및 결정적 실행 순서 생성 | 정상·누락·순환·경로·조건 입력 테스트 |
| T033 (REQ-020) | 저장된 Workflow 버전의 순차·조건 실행 및 실행 상태 조회, 기존 격리 백엔드 경유 | 모의 명령으로 실패 분기 → 승인 대기 → 성공 및 멱등 재요청 검증 |
| T034, T039 일부 | 두 노드까지 별도 Git Worktree에서 동시 실행, Join의 활성 선행관계 계산, 선언된 결과 병합, 실행 목록, 저장된 버전과 일치하는 그래프에 노드 상태 표시 | 별도 Git Worktree의 실제 동시 진입과 Join 전 산출물 통합 검증 |
| T035, T036 (REQ-021, REQ-026) | Worktree 기준 파일 아웃풋 확인, SHA-256 및 경로 기록, 입력 계약 검사, 승인 대상 변경 시 거부 | 실제 임시 파일로 승인 대기 중 변경 차단, 하드링크 거부 검증 |
| T037 일부 (REQ-022, REQ-035) | 일시정지·취소·재개, 확인된 실패 노드 재시도와 이전 결과 보관, 불확실 노드 재실행 차단 | 이전 성공 노드 유지, 실패 이력 보존, 중단 기록 검증 |
| T040 (REQ-005, REQ-023) | 고정 버전 Subgraph, 재귀 차단, 프로젝트 정의 이름·버전으로 연결하는 템플릿 가져오기·내보내기 | 이전 버전 재현, 재귀 거부, 프로젝트 간 복제 및 식별한 자격 증명 검사 |
| T038 (REQ-018, REQ-019) | 별도 Workflow 화면에서 노드와 연결 추가·삭제, 드래그, 속성, 계획 미리보기, 저장 및 다시 열기 | Windows 데스크톱 테스트에 편집·이동·저장·재조회 시나리오 추가 |
| T041, T042 일부 (REQ-024, REQ-025) | 프로젝트별 개발 Task, 고정 Workflow 버전, 기본 칸반 단계와 승인·실행 결과 동기화 | 단위 테스트에서 Task 준비→승인 대기→완료, 멱등 실행, 기존 Workflow 버전 보존 |

Workflow는 단일 실행 큐를 사용하며 독립 외부 노드 두 개까지 병행합니다. 병렬 Worktree는 선언한 파일만 병합하고 동일 경로는 충돌로 처리합니다. 병렬 작업본은 진단을 위해 보존하며, 프로젝트 기준 작업본에는 변경하지 않습니다. Live Map 카드 연결은 후속 구현입니다. Phase 5의 SDLC 및 Phase 6의 설치·최종 인수는 해당 Graph 실행 기반을 사용합니다. 데이터 이관 시험은 이전 V2 DB 사본으로 실행합니다.

| 영역 | 구현과 제한 |
| --- | --- |
| T042, T043 | 칸반 단계 표시 이름·순서·기본 Workflow 설정, 승인 대기함, Worktree의 Git 변경사항과 노드 결과 조회 |
| T044, T045 일부 | 검토 커밋과 GitHub 브랜치의 SHA 일치 확인, 명시적 PR 생성 및 불확실 요청 재조회, CI 통과 후 릴리스 후보 승인 기록. 배포 실행은 별도 작업이며 GitHub 연결은 모의 API로 검증합니다. |
| T048, T049 일부 | Task → Workflow 실행 → 노드·시도·실행 타임라인, 프로젝트별 보고·예약·누락 비용 집계. Live Map 세션 및 도구 로그 링크와 프로젝트 전체 예산 정책은 후속 구현입니다. |

## V3 Windows 개발 설치본

V3는 V2와 다른 설치 ID와 사용자 데이터 디렉터리를 사용합니다. 기본 경로에 설치한 V2에서 SQLite 프로젝트·정의·실행 이력과 Claude 모델·계보 설정을 첫 시작 시 별도 데이터 디렉터리에 복사합니다. SQLite는 WAL에 남은 커밋을 포함해 읽기 전용 스냅샷으로 복사하고, V3에서 마이그레이션합니다. 기존 V3 데이터가 있으면 복사를 건너뜁니다.

- T046, T047: 장애 대응을 포함해 기본 Workflow 8종의 모의 실행을 검증했습니다. 장애 발생 기록과 증상은 Task에 입력하며, 운영 설비 변경은 포함하지 않습니다.
- T051 일부: 기존 V2 상태 복사, V3 설치·실행 및 제거 시 데이터 디렉터리 보존을 검증합니다.
- V2 Worktree 파일, 브라우저 배치, DPAPI 키는 새 데이터 디렉터리에 복사되지 않습니다. 이전 실행은 V2에서 이어갈 수 있습니다. Windows 사용자에게 저장된 Claude Console 프로필은 재사용할 수 있습니다.
- 업데이트나 복구 전에 앱을 종료하고 `%APPDATA%\OMP Live Map V3` 데이터 디렉터리를 복사해 둡니다. 복원은 앱을 종료하고 기존 V3 디렉터리를 따로 보관한 뒤 백업본을 같은 위치에 복사합니다. V2는 기존 설치에서 계속 실행할 수 있습니다.
- 별도 위치의 V2 데이터를 새 V3 프로필로 가져오려면 `--import-v2-data-dir=<절대 경로>`를 사용할 수 있습니다. 기본 복사를 건너뛰고 시작하려면 `--skip-v2-import`를 사용합니다.

남은 인수 항목은 실제 Windows Docker·Claude 계정 파일럿, 실제 GitHub PR 및 배포 연동, 세션 도구 로그의 통합 추적, 프로젝트 전체 예산·기간별 성과 및 최종 요구사항 추적성 확인입니다. V3 개발 설치본은 최종 인수 전 검증용입니다.
