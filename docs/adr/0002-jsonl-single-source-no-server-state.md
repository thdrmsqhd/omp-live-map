# ADR-0002: 스냅샷의 원본은 jsonl 하나이고, 맵 서버는 자기 상태를 저장하지 않는다

**Date:** 2026-11-13
**Status:** Accepted (by grill-with-docs session)
**Source:** grill-with-docs session on 2026-11-13

## Context

ADR-0001로 맵 세션에는 rpc 이벤트와 기록 파일(jsonl) 두 경로로 같은 정보가 들어온다. TUI 세션은 rpc가 없어 jsonl만 있다. README는 "서버는 읽기만 하고 상태를 메모리에만 둡니다. 서버를 다시 띄우면 기록에서 다시 만듭니다."라고 정해 두었다.

"에이전트 오케스트레이션"을 맵 서버가 세션 간 흐름(A가 끝나면 B 시작)을 자동 실행하는 것으로 넓히면, 서버가 작업 그래프와 진행 상태를 디스크에 저장해야 하고 실패 처리·재시작 복구·비용 상한을 새로 정해야 한다.

## Decision

- 카드의 메시지·토큰·비용·툴 사용(스냅샷)의 원본은 jsonl 하나다. 맵 세션과 TUI 세션이 같은 수집 경로(`tail.js` → `ingest.js` → `snapshot.js`)를 탄다.
- rpc 이벤트는 진행 중인 글자·툴 호출·서브에이전트 활동을 보여 주는 임시 표시로만 쓴다. 기록에 써지면 버린다. 저장하지 않는다.
- 세션 기록은 omp만 쓴다. 맵 서버는 디스크에 아무것도 쓰지 않는다. 열어 둔 맵 세션 목록도 저장하지 않는다.
- 작업 분배는 omp 메인 에이전트의 `task` 툴이 한다. 맵 서버는 사용자 입력 없이 스스로 프롬프트를 만들어 보내지 않는다.
- 세션 간 연결은 수동 전달만 둔다. 사용자가 누를 때 세션 A의 마지막 답변을 세션 B의 프롬프트로 넘긴다.

## Consequences

- Good: 서버 재시작 뒤 화면은 기록에서 그대로 복원된다. 카드 하나에 코드 경로가 하나다.
- Good: README의 "모듈 하나가 상태 소유", "서버는 읽기만 함" 규칙이 유지된다. 바뀌는 문장은 프롬프트 전송 방식과 `busy` 설명뿐이다.
- Bad: 맵 세션의 토큰·비용 수치는 omp가 기록을 쓴 뒤에야 갱신된다. rpc의 `get_session_stats`보다 늦다.
- Bad: 새 세션의 기록 파일은 첫 메시지가 써질 때 생긴다(2026-11-13 확인: `get_state`만 보내고 종료하면 파일이 없다). 그 사이 카드는 `get_state.sessionFile` 경로를 id로 삼은 임시 노드로 그려야 한다. 새 세션을 항상 첫 프롬프트와 함께 열기로 해서 이 구간은 짧다.
- Bad: 서버가 맵 세션 목록을 기억하지 않으므로 재시작 뒤 "중단됨" 판정은 기록 파일 내용만으로 해야 한다. 판정 기준은 아직 확인하지 못했다.
- Bad: 자동 흐름이 필요해지면 이 ADR을 바꾸고 저장 형식·실패 처리·비용 상한을 다시 정해야 한다.
- Reversibility: hard. 원본을 rpc로 옮기면 `snapshot.js`와 카드 지표 경로가 둘로 갈린다. 자동 흐름 추가는 서버에 저장 상태를 처음 들이는 변경이다.

## Alternatives considered

- 맵 세션은 rpc가 원본, TUI 세션은 jsonl이 원본: 수치가 더 빨리 맞지만 카드 하나에 경로가 둘이 되어 제외.
- 맵 서버가 세션 간 흐름을 자동 실행: 완료 기준에 없고 서버 저장 상태·무인 실행 비용 문제가 따라와서 제외. 사용자가 수동 전달로 낮췄다.
- 맵 세션 목록을 파일에 저장하고 재시작 때 자동 `--restore`: 서버가 디스크에 쓰게 되고 사용자 확인 없이 비용이 나가서 제외.
