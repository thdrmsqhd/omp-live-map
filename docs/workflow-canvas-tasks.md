# Workflow를 Live Map에서 실행·관제·편집

기존 하네스 편집 브랜치를 기반으로 구현합니다. 첫 사용자는 관제에서 그래프 설계 없이 템플릿을 실행하고, 실행 중에는 기존 Live Map의 자유 배치 캔버스에서 단계를 보고 개입합니다.

## 요구사항

| ID | 사용자 요구 | 인수 기준 |
|---|---|---|
| WR-01 | 관제에서 실행 시작 | 프로젝트, 템플릿, 목표, 완료 조건을 고르면 Run이 시작됩니다. 준비가 필요한 하네스나 런타임은 실행 전에 표시합니다. |
| WR-02 | 진행 경로와 증거 확인 | 실행에 고정된 Workflow의 노드와 연결선이 Live Map에 나타납니다. 상태를 새로 받아도 카드 배치, 이동·확대 및 선택이 유지됩니다. 노드를 눌러 결과·산출물·시도 정보를 확인합니다. |
| WR-03 | 실패 및 승인 개입 | 재검증, 구현 보완 요청, 승인 또는 반려를 관제에서 수행합니다. 재검증은 현재 작업 공간을 쓰고 구현 보완에는 실패 근거를 전달합니다. 결과가 불확실하거나 이미 후속 작업이 실행된 경우 기존 안전 규칙을 적용합니다. |
| WR-04 | 같은 캔버스에서 필요할 때 편집 | 편집 모드에서 노드와 연결을 변경하고 Loop 반복 한도, 승인 및 하네스 설정을 확인합니다. 검증을 통과한 변경은 새 버전으로 저장하며 과거 Run은 시작 버전을 유지합니다. |
| WR-05 | 기존 제품과의 일관성 | 세션 카드, 열린 카드 위치와 배치 저장을 유지합니다. 기존 Engineering 화면과 새 관제 흐름이 같은 저장소·실행기를 사용합니다. |

첫 시나리오: Modbus 재접속 오류를 버그 수정 템플릿으로 실행합니다. 계획 승인을 거쳐 작업을 진행하고, 실패한 검증의 증거를 확인합니다. 검증을 재시도하거나 구현을 보완한 뒤 리뷰를 승인합니다. 편집 모드에서 그래프와 하네스 설정을 바꿔 새 버전을 저장하고, 과거 실행은 사용한 버전으로 다시 열립니다. 다른 프로젝트의 기능 개발 템플릿에도 같은 흐름을 적용합니다.

WC-02 검증 · 승인된 실행 환경 검사, 실패 시 정의 저장 롤백, 재요청 시 Run 중복 방지, 동일 템플릿 재사용, 목표·완료 조건 보존을 자동 검증했습니다.
