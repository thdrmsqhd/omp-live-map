## 세션 목록과 지도
- 세션 에이전트(main·sub)는 지도에 큰 카드로만 있고, 목록(`view/session-list.js`, 행 데이터 `viewmodel/session-rows.js`)이 일람을 맡는다. 열린 카드 상태(`openIds`·`BIGPOS`)가 목록 강조와 지도를 함께 결정하므로 열고 닫는 경로는 `openNode`·`closeCard`·`toggleCard` 한 곳을 쓴다.
- 목록 패널 폭·접힘은 `omp-map-sessions`, 큰 카드 좌표는 `omp-map-bigpos`에 저장한다. 세션 작은 카드 크기(`omp-map-subsize`)·카드 절대 좌표(`omp-map-manual`의 `card:` 키)·세션 원점은 더 쓰지 않는다.
- 세션 잡 카드는 그 세션에 열린 큰 카드가 있을 때만 지도에 올라온다(앵커 없음 → 미표시).

## 코드 편집기
- `view/editor-api.js`(fetch 래퍼) → `view/editor-mount.js`(Monaco jsDelivr CDN 지연 로드·언어 매핑·LSP→마커 변환) → `view/editor.js`(카드별 상태·DOM 골격·탭·상태바·Monaco 생성) → `view/editor-chrome.js`(탐색기 폭·접힘, 탭 클릭, 고정 탭, 브레드크럼) → `view/editor-split.js`(대화·편집기 경계 끌기) → `view/editor-explorer.js`(탐색기 트리·필터·우클릭 메뉴) → `view/editor-actions.js`(저장·F12 정의 이동·600ms 진단 디바운스) → `view/editor-open.js`(탭 닫기·`edDispose`·`openEditor(카드id, 경로, {pin})`) → `view/block-editor.js`(큰 카드 `editor` 블록, main 슬롯) 순서로 로드한다. `files` 블록은 없다: 파일 트리는 편집기 탐색기가 맡고 데이터(`TREES`·`loadTree`·`setCwd`)는 `viewmodel/files.js` 에 둔다. 저장된 블록 구성의 `files` 는 `cardBlockTypes` 가 `editor` 로 이전하고, 서브에이전트(sub) 카드에는 editor 를 넣지 않는다. 편집기는 chat 이 있는 카드에서 슬롯 `edit`(대화 오른쪽 `.col-ed`, 폭 `--edcol`)에, 없으면 `main` 에 놓인다. 편집기 안 요소 속성·클래스는 카드 전역 핸들러(`data-act`·`data-close`·`.x`)와 겹치지 않게 `data-edact`·`data-edclose`·`edx` 처럼 `ed` 접두어를 쓴다.
- 편집기는 카드 안 블록이다. 카드별 상태(`ED`: root DOM·Monaco·탭·미리보기 탭·탐색기 펼침/필터)와 파일 레코드(`ED_FILES`: 경로당 모델·mtime·dirty를 카드끼리 공유)는 `editor.js`가 단독 소유한다. 바디가 다시 만들어져도 root DOM은 살아 있고 `block-editor.js`의 mount가 다시 붙인다(`paint`는 숨김 여부만 맞춘다). 카드를 닫을 때 `closeCard`가 `edDispose`를 불러 인스턴스·모델을 dispose 한다. 편집기 안 휠은 root에서 끊고 포인터는 `CARD_INTERACTIVE`(`.edblk`)로 막아 지도·카드 끌기로 새지 않는다. 다른 파일은 DOM 상태를 새로 만들지 말고 이 함수를 쓴다. Monaco는 처음 열 때만 CDN에서 받고, npm 의존성은 두지 않는다.
## 관제 벽 (프로젝트 타일 격자 > Task > Workflow 단계 > 에이전트 > 서브에이전트)
- 화면은 두 모드뿐이다: `map`(관제 벽 `#umap`)과 `workspace`(세션 하나 전체 화면 `#stage`). 전환은 `view/monitor.js`의 `setMapMode`(저장 키 `omp-map-view-mode-v3`). 맵으로 돌아오면 떠날 때의 벽 위치(`UM.returnTo`)를 되살린다. 탭·설계 캔버스·칸반은 없다. 벽 안에서 프로젝트 하나를 화면 전체로 보는 것은 모드가 아니라 `UM.focus`(타일 key)다: `umapEnterFocus`·`umapLeaveFocus`(view/umap-input.js), 들어갈 때의 벽 위치는 `UM.focusReturn`, 타일 본문 스크롤은 `UM.scroll`(키 `wall|<key>`·`full|<key>`)에 따로 남아 Esc 로 같은 자리에 돌아온다.
- 펼치기·접기·의미 확대(배율별 정보 밀도)는 없다(타일·Task·세션 모두). 쉬는 타일이 작은 것은 내용대로 정한 크기(`umapTileSize`)이지 접기가 아니다 — 접기 단추·상태를 만들지 않는다. 카드는 배율과 상관없이 같은 문장·같은 크기이고, 좁은 타일에서는 카드 폭만 줄인다(`UMAP_AGENT.MIN_W` 260). 맵 카드 글자는 100%에서 12px 이상. 완료 Task 는 흐리게(`.um-dim`) 다 그린다.
- `model/umap-wall.js`(순수, 전역 없음): 벽 격자. `umapWallGrid({width,height})`(열 2~4: 타일 `TILE_MIN_W` 440 이상, 줄 칸 = 한 화면 8칸), `umapWallOrder(tiles, order)`(저장 순서 → 없으면 attention → running → idle, 최근 활동 순), `umapTileSize`(저장 크기 → 없으면 idle 1칸·나머지 `ACTIVE_H` 4칸(내용 높이 `need` 칸이 그보다 적으면 그만큼, 최소 `NEED_MIN` 2칸 — 반쯤 빈 타일 없음), `busy`(＋ Task 입력 중)면 일하는 크기), `umapWallRows(bodyPx, grid)`(타일 본문 높이 + 머리 `HEAD_PX` → 칸 수, 그리기가 `umapTileNeed`로 기본 1열 폭 배치를 재어 넘긴다), `umapWallPack(tiles, { cols, order, sizes, fitRows })`(순서대로 가장 위·왼쪽 빈 칸에, 겹침 없음. `fitRows`(= 격자 `rows`, 한 화면 칸 수)를 주면 크기를 저장하지 않은 일하는 타일을 벽이 한 화면을 넘지 않는 가장 큰 높이로 키운다), `umapWallRect`·`umapWallSize`(px), `umapWallSnap`(모서리 끌기 → 칸 수), `umapWallDrop`(놓은 칸 → 새 순서). 상수 `UMAP_WALL`.
- `model/agent-lines.js`(순수, 전역 없음): 에이전트 카드 문장. `umapAgentLines(node, { alias, ask, harness })` → `{ title, sub, state, label, color, goal, now, result, recent[3], counters }`, `umapActionLine(item)`(활동 → `calc.js 고침 (+4 −1)`·`node --test 실패`·`Cause 서브에이전트를 띄움`, omp·Claude 툴 이름), `umapNowLine`(→ `… 수정 중`·`테스트 실행 중 · npm test`·`서브에이전트 n개 대기`), `umapCmdName`(cd·환경 변수·powershell 껍질 벗기기), `umapAgentHeight(lines)`(카드 높이 — 배치와 그리기가 같은 값). 크기 상수 `UMAP_AGENT`, 상태 색 `UMAP_AGENT_STATE`. 서버 활동 요약의 `recent[]`·`now`는 구조 필드(cmd·add·del·names·who…)를 실어 보낸다(`server/activity.js` `view`).
- `model/task-map.js`(순수 계산, DOM·상태 없음): `umapOrderTasks`(개입 필요 → 진행 중 → 대기 → 완료), `umapTileLayout(band, { manual, width })`(타일 하나의 캔버스 배치. 폭 `UMAP.WIDE_W`(730) 이상이면 Task 카드 오른쪽에 단계를 늘어놓고 폭이 차면 다음 줄, 좁으면 Task 카드 아래에 단계를 하나씩 쌓는다. 단계에 세션이 있으면 가장 최근 시도의 세션(`umapStageAgent`)을 단계 카드 한 장에 합친다(높이 `umapStageHeight` = 머리(`STAGE_PAD·TOP·TITLE`, 칩이 있으면 `STAGE_CHIPS`) + 에이전트 문장 줄, 승인 대기면 + `APPROVE_H`(안내 2줄·앞 단계 결과 1줄·단추), 결과 `boxes[stage].merged` = 합친 세션 key, `alias`·`umapBoxOf`로 세션 key 에서 그 단계 카드를 찾는다). 그 서브에이전트는 `umapTree(child, maxW, stageKey, 1)`로 단계 카드 아래 한 칸 들여 가지를 치고, 예전 시도 세션만 따로 나무로 둔다(`UMAP_AGENT.INDENT`씩 들여 쌓기, 넓은 배치에서는 단계 칸이 나무 폭만큼 넓어진다). 옮긴 카드는 그 타일 캔버스 기준 dx·dy 이고 캔버스 폭 안으로 당긴다), `umapOverlap`, 선 높이 `UMAP.LINK_Y`, Workflow 편집 목록 연산(`umapInsertStage`·`umapMoveStage`·`umapRemoveStage`·`umapDropIndex(x, n, spots, y)`(줄을 넘긴 단계도 가장 가까운 칸)·`umapEditSpots`(＋ 자리)), `umapFitView`(벽 전체 보기에는 `max: 1`). 크기 상수는 `UMAP`이고 CSS(`css/umap.css`)와 같아야 선 끝이 맞는다. 배치는 배율과 무관하다.
- `viewmodel/task-map.js`: 상태 `UM`(프로젝트·task-map 응답·서랍·편집·벽 보기·`focus`·`scroll`·`autoFocus`)과 `localStorage`(`omp-umap-wall-v1` = `{ v: 1, order, sizes }` 타일 순서·크기, `omp-umap-manual-v2` 옮긴 카드). 예전 키 `omp-umap-bands-v1`(띠 순서·접힘)·`omp-umap-manual-v1`(띠 기준 카드 자리)·`omp-umap-view-v1`(한 맵 배율)은 읽지 않고 지운다. 벽 보기(`UM.view`)는 저장하지 않는다(열면 맨 위 100%). `umapBands`가 스냅샷 노드의 `sid`(JSONL 세션 id)와 서버가 준 단계별 `sessionId`를 맞춰 세션을 단계 아래에 놓고, 남은 세션은 폴더별로 프로젝트 타일에(프로젝트가 아니면 폴더 타일) 둔다. 세션 항목은 `umapAgentItem`이 그 세션의 서브 노드를 `parent`로 재귀 연결한 나무(`{ id, node, lines, children }`, `lines` = `umapLinesOf(node)`)이고 `umapFlatItems`로 펼친다. `umapTileStates(bands)` → 타일마다 `{ state: attention|running|idle, at, attention[] }`(attention = `umapAttention`: 승인 대기 단계 → 실패한 단계/보류 Task → 답을 기다리는 세션). 승인 대기 단계에는 `umapLinkBefore`가 앞 단계 결과 한 줄 `stage.before = { label, status, result }`(세션 결과 요약 → 단계 오류)를 싣는다. `UM.stageScope`(Task id → 'task'|'template', `umapScopeOf`)는 단계를 제자리에서 고칠 때의 저장 범위. `umapLayoutSnapshot`·`umapRestoreLayout`·`umapHasManualLayout`은 자동 배치로 되돌리기의 '되돌리기'(옮긴 카드·타일 순서·크기). 화면 갱신은 `viewUpdates.umap()`으로만 알린다. 서버 호출은 `viewmodel/task-map-actions.js`.
- view: `umap-render.js`(벽 그리기: 타일 머리(이름·상태·한 줄 지표·지금 상태 한 줄, 전체 화면이면 기간 지표·상태 칸) + 타일 본문 캔버스(타일마다 자기 `svg.um-links`), 다시 그려도 본문 스크롤 유지(`umapKeepScroll`·`umapRestoreScroll`), 처음 보일 때·'지금 볼 곳'이 바뀔 때 그곳으로 스크롤(`umapAutoScroll`), `UMAP_TILES`(key → { band, tile, rect, layout, meta })·`UMAP_LAYOUT.boxes`(모든 타일 상자 합본)·`UMAP_PACK`·`UMAP_GRID`) · `umap-agent.js`(에이전트 카드 HTML — `item.lines` 문장을 그린다(`umapAgentRows`는 합친 단계 카드도 쓴다), 제목은 `<button data-um="agent">`라 Tab·Enter 로 활동 서랍, 한 일 줄 = `act-item`(파일 있으면 diff, 없으면 대화 자리), 활동 서랍 `openAgentDrawer`: 수정 diff `POST /api/chat/edits`·명령·읽은 파일·대화 자리) · `umap-input.js`(타일 위 휠·빈 곳 끌기 = 그 타일 스크롤, 타일 사이 = 벽 이동, 머리 끌기 = 순서, 모서리 끌기 = 크기, 머리 두 번 = 전체 화면, 카드 끌기 = 타일 안 자리, `umapReveal`(타일로 벽 이동 + 본문 스크롤 + 반짝임), Workflow 편집 진입 `umapBeginEdit`/`umapEndEdit`: 그 프로젝트 전체 화면에서 편집하고 끝나면 벽으로, 포인터 캡처는 움직이기 시작한 뒤, 맵 키) · `umap-click.js`(타일 ⋯: 전체 화면·앞/뒤로·크기 자동으로·카드 되돌리기, 맵 도구 막대 ⋯ `umapWallMenu`, `umapResetLayout`(되돌리기 토스트), 단계 글자 제자리 고치기 `umapStageInline`·모델 메뉴, Task 제목 제자리 고치기, 개입 필요 이동) · `umap-edit.js`(＋ Task 한 줄, Workflow 편집 ＋·끌어 놓기) · `umap-drawer.js`(단계·하네스·루프·Task 서랍: `umapProp` 한 줄 = 이름 · 값 글자, 누르면 inlineEdit(여러 줄은 textarea)·제자리 메뉴로 그 자리 저장 — 입력 칸 폼·저장 단추 없음, 저장 범위 칩 `umapScopeChip`) · `umap-library.js`(한 정의 = 한 줄 표 `umlColumns`·`umlRow`, 칸 글자 제자리 고치기, 줄 ⋯ 복제·삭제, 펼치는 줄 없음) · `umap-topbar.js`(자원 한 줄 `CPU · RAM · WSL · Docker`과 서랍, 기존 인프라 동작 유지).
- 서버: `GET /api/engineering/task-map?project=`(읽기), `POST tasks/stage`·`tasks/workflow`(저장 범위 `task`|`template`), `POST workflows/remove`(Task가 쓰는 Workflow는 거부). 웹·데스크톱 모두 `core/engineering-api.js`로 같은 출처 HTTP를 부르므로 새 API는 서버 라우트(`server/edge/engineering-routes.js`)에만 더한다.
- 큰 카드의 무거운 블록은 workspace 모드의 활성 카드에서만 만든다(`card-virtualization.js`). 맵의 에이전트 카드는 가벼운 HTML 카드다. 맵 도구 막대 `#umap-tools`(라이브러리 · 전체 보기 · ⋯ · 알림 줄 `#umap-status` — `umapToast(text, { label, run })`면 되돌리기 같은 단추를 붙인다)는 `#umap-viewport` 위 40px 줄이라 타일을 가리지 않는다. `fit` 단추는 없다(전체 보기·키 0).

- F12는 Python이면 `/api/editor/definition` 으로, JS/TS면 Monaco 내장 TypeScript 서비스(`getTypeScriptWorker`)로 정의를 찾는다. Ctrl+클릭은 Python만 직접 처리한다. Python 진단은 서버가 주고 JS/TS 문법 오류는 Monaco가 스스로 마커를 단다.
